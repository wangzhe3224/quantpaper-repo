# 双层自研究（Bilevel Autoresearch）：对自身进行元自研究

**Yaonan Qu**<sup>∗</sup> · **Meng Lu**<sup>†</sup>

<sup>∗</sup>独立研究者，EdwardOptimization@gmail.com
<sup>†</sup>独立研究者，menglu_16@connect.hku.hk

## 亮点

- **核心思想**：一个由 LLM 驱动的外层循环通过阅读内层 *autoresearch*（自研究）循环的运行器代码、识别瓶颈、并生成与注入新的搜索**机制（以 Python 代码形式在运行时注入）**，对内层循环进行元优化——改进的是"未来改进如何被搜索"这一过程，而非一次性产出物。
- **基准 / 任务**：Karpathy 的 GPT 预训练基准——一个 5000 万参数的模型在固定 300 秒预算下训练；主指标为验证集每字节比特数（`val_bpb`）。
- **模型**：内层与外层循环使用**同一个** `DeepSeek deepseek-chat` 模型——无需更强的元层模型（尽管外层循环会消耗额外的推理 / 墙钟时间预算）。
- **硬件与预算**：三台独立的 **RTX 5090（32 GB）** 服务器；每次重复包含 30 次迭代的搜索预算。
- **实验设计**：受控的**四组消融**——A（仅 Level 1）、B（Level 1 + 1.5）、C（Level 1 + 1.5 + 2，完整双层）、D（Level 1 + 2）——所有变量保持恒定，每组 **3 次独立重复**。
- **核心发现**：完整双层配置（C 组）相对仅内层循环实现了 **5 倍改进**（−0.045 对 −0.009 `val_bpb`），而参数级调整（Level 1.5，B 组）**无可靠增益**（−0.006）。
- **所发现的机制**：Level 2 自主实例化了 **禁忌搜索（Tabu Search）**、**多尺度赌博机（Multi-Scale Bandit）** 与 **系统正交探索（Systematic Orthogonal Exploration）**（分别源自组合优化、在线学习 / MAB 与实验设计）——全部六次会话中代码均在首次尝试即生成成功（零次重试）。

## 摘要

如果自研究（autoresearch）本身就是一种研究，那么自研究就可以被应用于研究自身。我们字面意义上地采纳了这一想法：我们用一个自研究循环来优化自研究循环。

我们所构建其上的自研究系统——从 Karpathy 的单轨循环，到 AutoResearchClaw 的多批次扩展，再到 EvoScientist 的持久记忆——使用的搜索流程都是由人类设计的。我们追问：一个 LLM 能否自主地改进这一流程本身——阅读循环、识别瓶颈、并生成能够改变未来改进如何被搜索的新机制？

我们提出**双层自研究（Bilevel Autoresearch）**，这是一个双层框架：外层循环通过在运行时生成并注入作为 Python 代码的新搜索机制，对内层自研究循环进行元优化。内层循环优化任务；外层循环优化内层循环的搜索方式。两个循环使用同一个 LLM——在元层级并不需要更强的模型，尽管外层循环会消耗额外的推理与墙钟时间预算。这是智能体自我改进的一种机制层级视角：在我们的实现中，Python 代码是机制的载体，但技能（skills）、提示（prompts）、工作流（workflows）、脚本（scripts）、评估器（evaluators）、领域原则、世界模型假设与记忆模式（memory schemas）同样可以编码可修改的、塑造未来智能体行为的机制。

在 Karpathy 的 GPT 预训练基准上，元自研究外层循环相较仅使用标准内层循环实现了 **5 倍改进**（−0.045 对 −0.009 `val_bpb`），而未改变机制、仅在参数层面进行调整则不会带来可靠增益。外层循环从相邻搜索领域实例化了多种机制，包括组合优化、多臂赌博机与实验设计——且无需人类指定最终的机制设计。轨迹分析表明，这些机制之所以能提升性能，是因为它们打破了内层循环的确定性搜索模式，迫使搜索探索那些 LLM 先验所系统性地回避的方向。

这些实验在该基准上展示了第一个双层步骤：一个外层循环改进了内层循环的搜索行为。同一机制发现原则也指向了一条通往递归自举（recursive bootstrapping）的路径：为内层循环发现的机制可以被反馈回去，以改进元层循环本身。

## 1 引言

大型语言模型已经展现出引人注目的自导向科学迭代能力：给定一个任务，LLM 可以提出一项改动、执行一次实验、观察结果，并决定保留还是丢弃该改动。当这一过程被反复执行时，"提出–执行–评估"循环便构成了一种自动化研究 [Karpathy, 2026]。当其被实例化为神经网络超参数搜索时，我们将这一循环称为**自研究（autoresearch）**。

在抽象层面上，自研究是一个对研究动作进行闭环优化的过程。单个 LLM 反复提出一个干预，类似于序贯单点搜索；多批次自研究类似于批次或种群搜索；而持久记忆则改变了未来提案可用的状态。然而在我们所构建其上的系统中，这些搜索流程仍由人类设计师固定。Karpathy [2026] 引入了带保留/丢弃接受规则的单轨内层循环；AutoResearchClaw [AIMing Lab, 2026] 用多批次并行搜索对其进行了扩展；EvoScientist [EvoScientist Contributors, 2026] 增加了跨运行的持久经验记忆。这些都是有用的机制选择，但这些系统本身并不会发现或替换产生未来改进的搜索流程。

这自然引出一个问题：一个外层循环能否自主地完成同样的设计步骤——阅读代码、识别瓶颈、编写新代码？

我们给出了一个初步的肯定性证明（图 1）。我们提出**双层自研究（Bilevel Autoresearch）**，一个包含两个嵌套循环的双层框架：内层循环优化任务（提出超参数改动、训练、评估、保留或丢弃）；外层循环优化内层循环的搜索方式——通过阅读其代码、识别瓶颈、生成新的 Python 机制并在运行时注入。两个循环使用同一个 LLM，尽管外层循环会消耗额外的推理与墙钟时间预算；任何改进都源自双层架构，而非来自一个更强的模型。

核心对象是**机制（mechanism）**，而非本实现中所使用的特定表示形式。我们之所以采用 Python 代码注入，是因为代码是显式的、可执行的，且在激活前易于验证。更一般地，技能、提示、工作流、脚本、评估器、课程、领域原则、世界模型假设与记忆模式也都可以作为机制的载体，改变未来智能体的行为。因此，双层自研究瞄准的是**机制层级的自我改进**：改进一个智能体循环生成、评估、选择与修订未来改动的方式，而不仅仅是改进一个一次性的产出物。

这一框架也暗示了一条递归自举的路径。如果 Level 2 发现了改进 Level 1 的机制，那么同一发现原则原则上也可以被应用于元层循环本身。本文在经验上研究的是第一个双层步骤——一个外层循环改进一个内层循环——而将完整的递归自我应用留作未来工作。

> **图 1**：*双层自研究：内层循环优化任务输出；外层循环通过在运行时生成并注入新的 Python 代码来优化内层循环的搜索机制。*
>
> - **内层循环 —— 优化任务输出**：提出 → 训练 → 评估 → 保留 / 丢弃 → 更新最佳配置
> - **外层循环 —— 优化搜索机制**：分析轨迹 → 研究机制 → 生成代码 → 注入*（新机制 = Python 代码）*

我们在 Karpathy 的 GPT 预训练基准上，以一组受控的四组消融（第 3 节）评估该框架。

**贡献。**

1. 我们将自研究形式化为一个闭环搜索过程，并引入一个双层框架：其中一个外层循环优化内层循环的搜索 / 更新机制。
2. 我们通过一个 4 轮 LLM 对话实现外层，在运行时生成并以 Python 代码形式注入新的搜索机制。
3. 一组受控的四组消融表明，机制研究（Level 2）相对仅内层循环产生了 5 倍改进（−0.045 ± 0.030 对 −0.009 ± 0.002），而参数级调整（Level 1.5）不产生可靠增益。
4. 轨迹分析揭示了原因：所生成的机制（禁忌搜索、赌博机、正交探索）迫使搜索探索那些 LLM 默认搜索路径系统性回避的方向。
5. 我们澄清了主张的范围：代码只是可修改机制的一种载体，而递归自我应用是一个自然的扩展，并非本文已经确立的经验结果。

## 2 相关工作

### 2.1 自研究与 LLM 驱动的优化

Karpathy [2026] 引入了用于神经网络超参数搜索的范式性自研究循环：一个 LLM 阅读训练脚本，提出一个配置改动，在固定预算下执行训练，测量验证损失，并接受或拒绝该改动。反复迭代后，这构成了配置空间中一种由 LLM 引导的爬山（hill climbing），其中 LLM 的世界知识充当关于有前景改动的隐式先验，而训练结果则提供无梯度的反馈。

AutoResearchClaw [AIMing Lab, 2026] 通过多批次并行对该框架进行了扩展：多个候选配置被同时评估，其中最优者被晋升。这在不改变底层接受机制的前提下，提高了搜索的有效分支因子。

EvoScientist [EvoScientist Contributors, 2026] 引入了持久经验记忆：来自先前运行的教训被总结并注入到未来的提案中，从而实现跨运行的学习。这两项增强都是由人类研究者设计的——他们检视了前一系统的代码并识别出架构上的缺口。在这些系统中，结构性的决策——何时接受、如何提出、维护什么状态——是由人类设计师而非系统本身做出的。

### 2.2 双层优化

双层优化 [Colson et al., 2007, Sinha et al., 2018] 研究如下形式的问题

$$\min_\phi \, F(\phi, \theta^*(\phi)) \quad \text{subject to} \quad \theta^*(\phi) \in \arg\min_\theta f(\theta, \phi),$$

其中上层目标 $F$ 依赖于一个由 $\phi$ 参数化的下层问题的最优解。其应用包括元学习 [Franceschi et al., 2018]、神经架构搜索 [Liu et al., 2019] 与超参数优化 [Feurer and Hutter, 2019]。在我们的设定中，上层优化搜索机制 $\phi$（运行器代码），下层优化任务性能 $\theta$（训练配置）。与经典双层优化的关键区别在于，$\phi$ 是一个**程序**——一个由代码生成产生的离散产物——而非一个实值参数向量。我们在结构与算法意义上使用"双层"这一术语：本系统并未精确求解经典嵌套优化问题，而是实现了一个有限预算、不可微的类比，其中上层修改下层的搜索 / 更新机制。

### 2.3 用于研究的 LLM 代码生成

AlphaCode [Li et al., 2022] 与 Codex [Chen et al., 2021] 表明，LLM 能够根据自然语言规约编写功能正确的程序。FunSearch [Romera-Paredes et al., 2024] 将此扩展到科学发现：用一个 LLM 迭代地生成并评估数学程序，在组合数学中找到了新结果。最直接相关的是 LLM 驱动的算法设计这一脉络 [Liu et al., 2024, Lehman et al., 2023]，其中 LLM 提出新颖的算法变体，再在基准任务上对其进行评估。我们的 Level 2 智能体将同样的代码生成能力应用于一个不同目标：它不生成任务层级的程序，而是生成在运行时注入到内层循环中的搜索机制代码。

### 2.4 元学习与算法配置

元学习 [Hospedales et al., 2021] 通过跨任务分布进行优化，训练模型从少量样本中高效学习。算法配置 [Hutter et al., 2011] 与算法选择 [Rice, 1976] 为给定问题实例在候选算法或参数设置之间做出选择。组合方法（portfolio methods）[Xu et al., 2008] 维护一个算法库并从中选择。双层自研究在相近的精神下运作——外层循环选择或生成一个搜索机制——但它使用 LLM 代码生成，而非基于梯度的元优化或固定组合。

### 2.5 产物层级与机制层级的自我改进

许多智能体自我改进系统修改的是塑造未来行为的外部产物，如提示、可复用技能、工作流、记忆、框架（harness）状态或代码片段。这些产物之所以重要，是因为它们影响智能体接下来会做什么。然而，改进一个产物，与改进那个生成、评估、修订与部署未来产物的机制，是两回事。诸如 ADOPT [Zhao et al., 2025] 这类提示与流水线优化方法，把语言产物当作一个固定多步 LLM 流水线内可优化的参数。诸如 PiEvo [Pu et al., 2026] 这类原则演化方法则瞄准另一种载体：它们将科学发现视为对一个不断扩展的原则空间进行贝叶斯优化，允许智能体精炼指导假设生成的科学先验与世界观。双层自研究直接瞄准这一机制层级的对象。当前的实现将机制表示为可注入的 Python 代码，但当其他载体改变一个智能体循环的提案、评估、选择或更新行为时，同样的形式化也适用于它们。

**并发与后续工作。** 自本文 2026 年 3 月 24 日的初始 arXiv 版本以来，若干相关系统探索了技能、产物、框架与流程层级的自我改进。Meta-Harness [Lee et al., 2026] 在 LLM 应用的框架代码上进行搜索，而 Continual Harness [Karten et al., 2026] 则从轨迹中在线地适配提示、子智能体、技能与记忆。GEAR [Jeddi et al., 2026] 用基于种群的多研究状态搜索取代单路径自研究，并研究了一个其控制器可在运行期间演化的变体。Discovering Cooperative Pipelines [Gallego, 2026] 研究了面向序贯社会困境的双层自研究，其中一个外层编码智能体编辑内层策略合成流水线中的提示、反馈函数、辅助库与迭代逻辑。聚焦技能的工作优化可复用的技能产物：SkillEvolver 将技能学习构建为一种元技能 [Zhang et al., 2026a]，SkillOpt 将技能文档训练为外部智能体状态 [Yang et al., 2026]，而 Huang et al. [2026] 将技能结构与内容优化构建为一个双层问题。AEvo [Zhang et al., 2026b] 在精神上尤为接近：一个元智能体编辑控制未来演化的流程或智能体上下文，而不是直接提出下一个候选。我们将这些工作视为互补性的、后续出现的、把外部智能体产物作为有用干预面的实例。然而在我们的框架中，框架只是众多机制载体之一：技能、代码、提示、工作流、评估器、科学原则、世界模型假设与记忆模式，都可以编码塑造未来改进的提案、评估、选择或更新逻辑。

### 2.6 本文的定位

双层自研究与上述自研究系统之间的关键区别，在于外层循环所瞄准的目标。Level 1.5 最接近现有的外层循环（课程调度器、自适应配置），因为它调整的是既有机制的参数。Level 2 则在范畴上不同：它生成代码来修改或替换搜索机制的结构性组件。据我们所知，此前并不存在这样的自研究系统：一个自主的外层循环使用与运行内层循环相同的模型，编写并注入在运行时修改内层自研究循环结构逻辑的代码。许多后续的技能、框架与工作流系统都可以透过这一视角被看作相关的载体层级实例：它们往往优化有用的产物或智能体脚手架，而双层自研究则把这类产物框定为一种更深层的搜索 / 更新机制的可能表示形式。

## 3 方法

### 3.1 框架概述

双层自研究包含三个嵌套层级（图 2）：**Level 1** 优化任务；**Level 1.5** 调整搜索参数；**Level 2** 以 Python 代码生成新的搜索机制。所有层级都使用同一个 DeepSeek `deepseek-chat` 模型。

### 3.2 Level 1：内层自研究循环

内层循环实现了标准的自研究周期 [Karpathy, 2026]。在每次迭代 $t$：

1. LLM 接收当前的 `train.py`（冻结于最佳已接受配置）、活动可编辑参数列表、任何已冻结参数，以及由 Level 1.5 注入的一条策略性指导字符串。
2. LLM 提出一项改动：一组参数名–值对，以及一句话假设。
3. 该改动被应用到 `train.py` 的一份工作副本上，训练在固定 300 秒预算下运行。
4. 若所得 `val_bpb` 低于当前最佳，则保留该改动（更新最佳副本）；否则丢弃。

迭代预算固定为每次重复 30 次。初始配置锁定 `DEPTH=8` 与 `ASPECT_RATIO=64` 以防止架构尺寸变化；所有其他参数（`LR`、`WEIGHT_DECAY`、`WINDOW_PATTERN`、`HEAD_DIM`、`TOTAL_BATCH_SIZE` 等）均可编辑。

### 3.3 Level 1.5：外层搜索策略循环

Level 1.5 每 5 次内层迭代执行一次。它接收提案与结果的完整轨迹，并产生一次 `SearchConfig` 更新：

- 冻结那些已被提出 ≥ $k$ 次且净改进为零的参数（默认 $k = 3$）。
- 解冻那些已被冻结、但自搜索移动到新区域以来尚未被探索过的参数。
- 注入一条指导字符串，指示内层循环优先处理探索不足的参数。

Level 1.5 能够重定向搜索的多样性，但无法改变提案生成逻辑、接受准则或循环结构。这些结构性改变需要 Level 2。

> **图 2**：*双层自研究架构。Level 1（蓝色）运行标准的提出–训练–评估循环。Level 1.5（琥珀色）每 5 次迭代调整搜索参数。Level 2（绿色）通过一次 4 轮研究会话生成新的 Python 机制并在运行时注入。*
>
> 三层级双层架构：
> - **Level 1 —— 内层循环**：提出超参数 → 训练（mini-run）→ 评估 `val_bpb` → 保留？/ 丢弃？→（`保留` → 更新最佳配置）
> - **Level 1.5 —— 外层配置**：观察轨迹 → 分析轨迹 → 冻结 / 解冻参数 → 注入指导*（外层周期约每 5 次迭代）*
> - **Level 2 —— 机制研究**：探索 → 批判 → 规约 → 生成代码 → 注入新算子

### 3.4 Level 2：机制研究与代码注入

Level 2 每 2 个外层周期执行一次。它进行一次 4 轮结构化对话，每轮只做一次 LLM 调用：

1. **探索（Explore）**。LLM 阅读完整的 `runner.py` 源码与搜索轨迹。它审视相邻领域的机制（组合优化、在线学习、实验设计、贝叶斯优化），并提出候选改进。
2. **批判（Critique）**。LLM 针对所观察到的失效模式（例如重复提案、参数固着）评估候选机制，并选出最有前景的一个。
3. **规约（Specify）**。LLM 编写精确的接口规约：类名、构造函数参数、带签名的方法，以及 `runner.py` 中的集成点。
4. **生成（Generate）**。LLM 编写完整、可运行的 Python 代码，实现所规约的机制，包括调用它所需的任何对 `runner.py` 的修改。

> **图 3**：*Level 2 研究会话。每次会话进行四次 LLM 调用，产出一个在注入前经过验证的 Python 模块；若被接受，则修改内层循环的搜索行为。*
>
> Level 2 研究会话（4 次 LLM 调用）：**探索**假设 → **批判**选定假设 → **规约**规约 + 接口 → **生成**代码（Python 模块）→ **验证并注入**（通过 / 失败 → 回退）

所生成的代码就地修补 `runner.py`，并在激活前通过 `importlib` 动态加载进行验证。若导入成功，被修补的运行器替换当前活动运行器；若失败，则从补丁前备份恢复原运行器。这一"验证即回退"机制可防止导入期失败损坏活动运行器。

### 3.5 算法

**算法 1** *双层自研究（C 组配置）*

```
输入：baseline train.py，运行器 ϕ0，预算 T = 30，K = 5（外层周期），M = 2（L2 周期）
θ ← 基线配置；ϕ ← ϕ0；t ← 0；outer_cycle ← 0
BestVal ← EvaluateBaseline(θ)
guidance ← ∅；frozen ← ∅；trace ← ∅
while t < T do
    for k = 1 to K do
        proposal ← LLMPropose(θ, ϕ, guidance, frozen)
        θ′ ← θ ⊕ proposal
        val ← Train(θ′, budget = 300s)
        accepted ← val < BestVal
        if accepted then
            θ ← θ′；BestVal ← val
        end if
        trace ← trace ∪ {(proposal, val, accepted)}
        t ← t + 1
    end for
    guidance, frozen ← Level1.5(trace)
    outer_cycle ← outer_cycle + 1
    if t < T ∧ outer_cycle mod M = 0 then
        ϕ′ ← Level2Research(ϕ, trace)
        if ValidateImport(ϕ′) then
            ϕ ← ϕ′
        else
            回退 ϕ
        end if
    end if
end while
return θ
```

> **图 4**：*全部 12 次运行（4 组 × 3 次重复）的运行最小 `val_bpb` 随迭代的变化。细线：单次重复；粗线：组均值。一旦 C 组与 D 组的搜索轨迹转向 `TOTAL_BATCH_SIZE` 减小，便出现急剧下降。*（图：横轴为迭代 0–30，纵轴为最佳 `val_bpb`（运行最小值）≈ 1.04–1.11；标注了 L2 干预点。）

```python
class TabuSearchManager:
    def __init__(self, tenure=5, thresholds=None):
        self.tabu_list = []
        self.tenure = tenure
        self.distance_thresholds = thresholds or {}

    def is_tabu(self, config, iteration):
        # Remove expired entries
        self.tabu_list = [e for e in self.tabu_list
                          if iteration <= e["expires_at"]]
        for entry in self.tabu_list:
            for param, tabu_val in entry["config"].items():
                if param in config:
                    try:
                        diff = abs(float(config[param]) - float(tabu_val))
                        thresh = self.distance_thresholds.get(param, 0.0)
                        if diff <= thresh:
                            return True  # too close, blocked
                    except (ValueError, TypeError):
                        if config[param] == tabu_val:
                            return True
        return False  # allowed
```

> **图 5**：*一份 Level 2 生成机制（禁忌搜索管理器）的摘录。这段代码——完全由 LLM 在研究会话中编写——阻止内层循环重访近期已探索的参数区域，从而打破在 A 组中观察到的确定性提案模式。*

三个已激活的具名机制分别是：**禁忌搜索管理器**（维护一个近期已访问参数区域的禁忌列表，阻止 LLM 重复提出相同的改动）；**多尺度赌博机提案器**（将参数选择视为一个多臂赌博机，在不同尺度上平衡各参数的探索与利用）；以及**系统正交探索**（迫使 LLM 探索正交的参数维度，防止过度聚焦于单一参数）。每个已激活的具名机制都源自一个不同的相邻优化领域。Level 2 并未被告知要实现哪个具体机制，尽管提示中暗示了一些宽泛的邻近领域。

### 4.3 搜索行为分析

四个组别展现出定性上不同的搜索轨迹。

**A 组：近乎确定性的重复。** 三次重复从同一基线出发，遵循几乎相同的提案序列：第 1 次迭代尝试增大 `TOTAL_BATCH_SIZE`（丢弃）；第 2 次迭代减小 `WEIGHT_DECAY`（保留，$\Delta \approx -0.008$）；第 3 次迭代设置 `WINDOW_PATTERN="SSSS"`（保留，$\Delta \approx -0.002$）；第 4–30 次迭代重复这两项相同的改动，最多累积 22 次连续丢弃。给定相同状态，LLM 每次都生成几乎相同的提案。

**B 组：被重定向但有界。** Level 1.5 正确识别出停滞的参数并重定向搜索：到第 2–3 个周期，外层循环冻结 `WEIGHT_DECAY` 与 `WINDOW_PATTERN`，并将搜索重定向至 `LR`、`UNEMBEDDING_LR`、`MATRIX_LR` 与 `FINAL_LR_FRAC`。B 组比 A 组探索了更多参数，但取得的改进幅度相近，因为它仍运行在相同的结构性保留 / 丢弃框架之内。

**C 组：Level 2 机制解锁新方向。** C 组 R1 与 R3 的决定性事件是发现减小 `TOTAL_BATCH_SIZE`（从 219 降至 217 或 218），这产生了 −0.039 到 −0.065 的改进——大约是 A 组或 B 组所找到的任何单一改动的 5–8 倍。

**D 组：缺少外层循环指导的 Level 2。** D 组的模式更为含糊：R2 与 R3 独立地发现减小 `TOTAL_BATCH_SIZE`（D2 达到 217，D3 达到 218），产生 −0.063 与 −0.039 的改进。然而，逐重复报告显示，D 组生成的机制补丁并未被成功应用或验证，因此这些重复无法干净地证明仅靠成功的机制注入就导致了这些增益。R1 未能受益：它的两次 Level 2 会话生成的机制（`diversity_enforcer` 与 `fixation_detector`）未通过导入验证，使其只能以裸 Level 1 运行而无机制注入；内层循环无法自行发现批大小方向。Level 1.5 的缺失意味着没有聚焦的参数冻结指导来引导 Level 2 的注意力；加上 R1 的机制应用失败，这使得 D 组的结果（±0.031）比 C 组各重复更为多变——在 C 组中，Level 1.5 提供了更丰富的轨迹上下文。D 组的机制会话产物与逐重复报告已包含在代码库中。

### 4.4 `TOTAL_BATCH_SIZE` 的发现

所有实验中最具影响力的发现是：在 RTX 5090 上、300 秒训练预算下，将 `TOTAL_BATCH_SIZE` 从 219 减小到 217–218 会显著改善 `val_bpb`。其机制很直接：更小的批大小在固定时间预算内产生更多梯度步，并为这个 5000 万参数模型带来更好的收敛。原始的 219 批大小似乎更匹配原始基准所采用的面向 H100 的设定；在我们的 RTX 5090 配置中，运行 SDPA 而非 Flash Attention 3，更小的批大小在固定墙钟预算内产生了更多梯度步。

A 组与 B 组都出于相同原因错过这一方向：DeepSeek 的默认搜索路径首先尝试增大 `TOTAL_BATCH_SIZE`（一种隐式的"批越大越好"偏置）。在增大被丢弃后，A 组重复该尝试；B 组的外层循环在该次失败后冻结了 `TOTAL_BATCH_SIZE`，从而完全阻断了减小方向。只有高性能的 Level 2 条件重复——C 组 R1/R3 与 D 组 R2/R3——将搜索推向了减小方向。在 C 组中，相关的活动机制是禁忌搜索（阻止重访失败方向）与正交探索（强制维度多样性）。在 D 组中，同一方向也出现在所报告的轨迹中，但机制补丁并未被成功应用或验证，因此这些重复不应被解读为成功机制注入的干净证据。

## 5 讨论

### 5.1 假设检验

实验设计由四个假设所驱动。

**H1（B 组 > A 组）：未获支持。** B 组的平均改进（−0.006 ± 0.006）在数值上劣于 A 组（−0.009 ± 0.002），但鉴于 $n = 3$，这一差异并无实质意义。外层循环（Level 1.5）增加了搜索多样性——B 组比 A 组探索了更多参数——但在 30 次迭代预算内，这种多样性并未转化为更大的改进。B 组的 R1 取得了几乎为零的改进（−0.000），是所有组所有重复中最差的结果。外层循环正确地冻结了停滞的参数，但在这样做之后，LLM 在剩余搜索空间中找不到更好的方案。

**H2（C 组 > B 组）：获支持。** C 组的平均绝对改进（−0.045 ± 0.030）是 B 组（−0.006 ± 0.006）的 7.5 倍。尽管方差较高（±0.030），三次重复中有两次产生了戏剧性改进（−0.065、−0.058），且 C 组与 B 组之间的分离相对于组内方差较大，提供了有意义的证据表明 Level 2 在 Level 1.5 之上增添了价值。

**H3（Level 2 自主生成并注入新机制）：获支持。** 在 C 组的三次独立重复中，Level 2 从三个不同的活跃领域（组合优化、在线学习、DOE）生成了机制，而未被告知要实现哪个具体机制——尽管 Level 2 的提示暗示了一些宽泛的邻近领域（第四个领域，贝叶斯优化，曾被尝试但因缺少依赖而被回退）。所有六次会话中代码均在首次尝试即生成成功（零次重试）。六份生成的代码产物中有五份通过导入验证并被激活；在已激活的具名机制中，Level 2 实例化了禁忌搜索、多臂赌博机探索与系统正交探索。

**H4（D 组 ≈ 无 Level 1.5 的 C 组）：有启发性但不 conclusive。** D 组的均值（−0.034 ± 0.031）低于 C 组（−0.045 ± 0.030），但鉴于 $n = 3$，这一差异处于两组方差之内。D 组在三次重复中的两次产生了大幅改进，这表明移除 Level 1.5 并不一定阻止强劲的结果。然而，逐重复报告显示 D 组生成的机制补丁并未被成功应用或验证，因此 D 组并非对"无 Level 1.5 时成功 Level 2 注入"的干净检验。其余证据表明，Level 1.5 可能通过丰富 Level 2 所阅读的搜索轨迹来提供适度的鲁棒性，但仍需要更干净的消融。

### 5.2 为何 C 组的 R2 表现较弱

C 组的 R2 仅取得 −0.011 的改进，与 A 组、B 组相当，尽管它也接收了 Level 2 机制。最可能的解释是机制质量：R2 的 Level 2 生成了多尺度赌博机提案器——它虽然有效且被正确注入，但在迫使搜索探索批大小维度方面，可能不如 R1 的禁忌搜索管理器或 R3 的正交探索有效。次要因素是计算开销：每次 Level 2 研究会话额外增加约 3 分钟墙钟时间与四次额外的 LLM 调用。由于我们的实验预算固定的是内层迭代次数而非总墙钟时间，这一开销不会减少内层评估次数；它应被解读为双层架构的一项额外成本。

### 5.3 机制层级的诠释

主要教训并非"Python 代码是一种享有特权的自我改进产物"。相反，代码只是可修改机制的一种便利载体：它使提案、探索、选择与更新逻辑足够显式，从而可被检视、生成、验证、注入与回滚。当其他产物改变一个智能体循环的未来行为时，它们也能扮演同样角色。一项技能可以编码可复用的程序性策略；一个提示可以改变智能体的提案先验；一个工作流可以改变工具与子智能体之间的控制流；一个评估器可以改变哪些候选得以存活；而一项科学原则或世界模型假设可以改变智能体所搜索的假设空间。从这一视角看，双层自研究最好被理解为**机制层级的自我改进**：外层循环修改的是未来改进如何被生成，而不仅仅是当前回合使用哪个产物。

这也澄清了递归的主张。这些实验展示了一个第一层级的双层步骤：Level 2 改进了 Level 1 的搜索行为。如果某个被发现的机制能可靠地改进 Level 1，那么同一机制发现原则原则上也可被应用于 Level 2 自身。这样的递归自举将需要额外的评估关卡、版本管理、回滚，以及证据表明元层过程是改进而非仅仅改变。因此，我们将完整的递归自我应用视为一个自然的扩展，而非本实验已经确立的经验结果。

### 5.4 局限性

**样本量小。** 每组三次重复不足以进行严格的统计比较。C 组的标准差（±0.030）是其绝对均值的 67%，表明变异性很高。可靠的估计将需要每组 $n \geq 10$ 次重复。

**基线方差。** 由于数据顺序与权重初始化带来的训练随机性，基线 `val_bpb` 在各重复间存在变化（1.094–1.114）。使用 $\Delta = \text{best} - \text{baseline}$ 可缓解但无法消除这一问题；较低的基线留下的改进余地更小。未来工作应使用固定随机种子或报告基线归一化的指标。

**单一基准。** 所有结果都基于一个任务：在 RTX 5090 上、300 秒预算下对 5000 万参数的 GPT 进行预训练。向其他模型规模、训练预算或任务的泛化能力尚未得到证明。

**载体局限。** 这些实验将机制实例化为 Python 代码。该框架在概念层级是表示无关的，但本文并未系统地评估技能、提示、工作流、评估器、科学原则、世界模型假设或记忆模式作为替代机制载体的效果。

**递归局限。** 这些实验展示了一个外层循环改进一个内层循环。它们并未展示无界的递归自我改进，也未证明为 Level 1 发现的机制将改进 Level 2。递归自举仍是一个未来的评估目标。

**动态加载的脆弱性。** 一次预备性运行被作废，原因是 Level 2 的动态加载流水线中存在一个 `sys.modules` 注册 bug，导致所有机制注入都静默地回退到原始运行器。我们在进行所报告的三次重复之前修复了该 bug。这一事件凸显了运行时代码注入的脆弱性：没有报错的静默回退是一种危险的失效模式。

**外部依赖暴露。** Level 2 没有任何约束来阻止它导入外部库。六份生成的机制中有一份（GP Regressor）需要 `sklearn`，而该库未安装。"验证即回退"机制正确地处理了这一情况，但对任意依赖的暴露仍是一个可靠性风险。

**提示诱导的领域偏置。** Level 2 的提示显式地建议了候选领域（组合优化、强化学习、进化算法、贝叶斯优化）。这种指导是一把双刃剑：它阻止智能体生成无关或退化的机制，但也把可发现机制的搜索空间约束在提示作者所预期的领域之内。Level 2 在无约束提示下是否会发现同样有效——或截然不同——的机制，仍有待检验。

**无稳定性保证。** 运行时机制注入可以改善搜索行为，但也可能产生脆弱的补丁、评估器过拟合或不安全的自我修改。本系统依赖导入验证与失败即回退，而非形式化的收敛或稳定性保证。

### 5.5 未来工作

关键方向包括：在固定随机种子下扩展到 $n \geq 10$ 次重复以获得统计功效；在多个基准（不同模型规模、任务、预算）上评估以检验泛化能力；测试诸如技能、提示、工作流、评估器、科学原则、世界模型假设与记忆模式等替代机制载体；度量被接受的机制是否在各种子与任务间改变了内层循环未来的搜索行为；以及研究 Level 2 的代码生成质量是否会因更丰富的接口规约或测试框架而提升。

## 6 结论

双层自研究证明，一个由 LLM 驱动的外层循环能够通过在运行时生成并注入新的搜索机制，自主地改进一个自研究循环。在 Karpathy 的 GPT 基准上，Level 2 相对仅内层循环产生了 5 倍的 `val_bpb` 改进（−0.045 对 −0.009），而参数级调整（Level 1.5）不产生可靠增益。所生成的机制——源自组合优化、在线学习与实验设计——似乎通过迫使搜索探索那些 LLM 默认搜索路径所回避的方向来提升性能。

代码、逐重复报告与机制会话产物可在 <https://github.com/EdwardOptimization/Bilevel-Autoresearch> 获取。

核心原则在该基准的第一个双层层级上得到了经验支持：自研究能够改进自身的搜索机制。这一机制不必局限于 Python 代码；代码只是技能、提示、工作流、评估器、脚本、领域原则、世界模型假设与记忆模式等众多可执行载体之一，它们都能塑造未来智能体的行为。更长期的递归主张是一条路径，而非一个已完成的结果：为内层循环发现的机制或许可以被反馈回去以改进元层循环本身，但要证明稳健的递归自我应用，仍需进一步的实验与更强的验证关卡。
